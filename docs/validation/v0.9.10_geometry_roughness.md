# v0.9.10 geometry and elliptical roughness verification

This follow-up extends the existing external-provider release without changing
its version. The [method assessment](../elliptical_roughness_and_reporting.md)
distinguishes source smooth models, the opt-in rough hydraulic estimate,
smooth HTC approximation and unmodelled ellipse fittings.

The [machine-readable receipt](v0.9.10_geometry_roughness_test_summary.json)
records **1355 distinct passing public tests**: 1326 selected regressions and
29 disjoint external-provider tests. The selected regressions include the
29 new geometry/reference/roughness checks. Run the
[explicit selection](v0.9.10_geometry_roughness_test_selection.json) plus
`core/tests/external_outside_provider_test.py` with pytest. Verification used
Python 3.12.8 and CoolProp 6.6.0.

Checks cover physical rectangular-fin area/count/thickness, provider-independent
geometry, unavailable SHIFTED minimum area, explicit provider reference areas,
separate thermal/hydraulic references, independent permissions, invalid
roughness, smooth regression, monotonic roughness, Darcy/Fanning conversion,
hydraulic-point diagnostics, ordinary Rating/Simulation and unchanged thermal
physics under the authorized approximation. Existing local-path and
circular/continuous/serrated/source restrictions remain tested.

Private engineering evidence remains outside the public package: 15 controlled
water/oil sensitivity evaluations, original notebook source preservation,
exact pre-existing numerical baselines and three workbook round trips across
SHIFTED, conventional ellipse and round geometries. No manufacturing roughness
was assigned. Calibration data and VDI implementation hashes remain unchanged.

Runtime, repository and installed distribution remain 0.9.10. Fresh wheel
inspection verifies all 279 public Python modules byte-for-byte and excludes
private files/data. The earlier external-provider receipt is retained as a
historical record. A full wet-suite pass is not claimed; its documented
backend and unbounded historical-test limits remain outside this change.

These are implementation/regression checks, not experimental validation of
rough elliptical flow or an external provider's private calibration.
